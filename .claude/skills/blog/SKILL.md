주제 하나를 글로 깊게 판다. 쇼츠 영상이 3분 안에 이유까지 말하는 것이 목표라면,
글은 그 이유의 **근거를 직접 보여 주는 것**이 목표다(공식 문서 원문, 계산 과정, 직접 돌린 실험).
중간에 사용자에게 확인받지 않고 두 파일을 다 쓴 뒤 보고한다. 결과는 초안이며 사용자가 다듬어서 올린다.

## 호출

```
/blog <주제>
```

입력: $ARGUMENTS

(위가 비어 있거나 치환되지 않았으면 사용자 메시지에서 찾는다.)

- 입력은 **주제**다. 예: `/blog MySQL 트랜잭션 격리 수준`
- 사용자가 참고할 영상 폴더를 함께 적었을 때만 그 영상을 재료로 쓴다.
  예: `/blog MySQL 인덱스는 어떻게 빠르게 찾을까 — 0_mysql_인덱스란_무엇이고_왜_쓸까 영상 참고`
- 사용자가 영상을 적지 않았으면, 같은 주제의 영상 폴더가 있어도 찾아 읽지 않는다. 조사부터 한다.

## 결과물

- 폴더: `video_making/z_블로그작성/<N>_<주제 slug>/` (N = 그 안 번호 폴더 최댓값 + 1, 0부터)
- `본문.md`: 블로그(티스토리)에 올릴 글. 제목 줄 없이 요약 인용문부터 시작한다(제목은 티스토리 제목 칸에 넣는다).
  - 온라인 출처(공식 문서 등)에 근거 번호 `[1]`, `[2]`…를 달고, 글 끝에 링크 목록을 둔다.
  - 계산과 실험은 본문 안에서 직접 보여 준다(식, SQL, 핵심 출력).
- `참고자료.md`: 블로그에 올리지 않는 작업 노트. 출처 원문 인용, 계산 과정, 실험 명령과 전체 출력이 들어간다.
  사용자가 글의 사실을 다시 확인하거나, 이 글로 영상을 만들 때 쓴다.
- 폴더에는 이 두 파일만 둔다.

## 가장 중요한 것

1. **좁게 잡고 깊게 다룬다.** 쇼츠 스킬과 같은 원칙이다. 글이 답할 질문을 하나 정하고, 답안(항목마다 '왜')을 먼저 쓴다.
   글은 길이 여유가 있으니 영상보다 깊이 들어간다. 범위를 넓히지는 않는다.
2. **모든 사실 주장에는 독자가 확인할 수 있는 근거가 있다.**
   - 온라인 출처로 뒷받침하는 문장에는 `[n]`을 단다(글 끝 목록에 URL).
   - 계산과 실험은 본문에서 직접 보여 준다.
   - 로컬 파일(`참고자료.md`)을 근거로 가리키지 않는다. `[E1]`, `[C1]`이나 "참고자료에 적었다" 같은 표시를 쓰지 않는다.
   - 근거를 찾지 못한 주장은 빼거나, "확인하지 못했다"고 밝힌다.
3. **지어낸 출력은 쓰지 않는다.** 본문의 명령 출력(EXPLAIN 결과, 실행 시간 등)은 직접 돌려서 나온 것만 쓴다.
   돌리지 못했으면 출력을 빼거나, 바로 위에 "예시(실제 출력 아님)"라고 적는다.
4. **입문자가 따라올 수 있게 쓴다.** 새 용어는 처음 나올 때 한 문장으로 풀고, 원리는 구체적인 예 하나로 보여 준다.
5. **쇼츠 영상은 언급하지 않는다.** 참고 영상을 재료로 받았어도 글에는 영상 이야기를 쓰지 않는다(사용자 요청).

## 단계

모든 명령은 `video_making/`에서 실행한다. `$SK`는 이 스킬 폴더 `~/Documents/video_making/.claude/skills/blog`를 뜻한다.

### 1. 폴더 만들기

```bash
python3 .claude/skills/blog/scripts/new_post.py "<글 주제>"
```

`<글 주제>`는 사용자가 준 주제를 그대로 쓴다. 출력된 경로가 작업 폴더다.
`already exists`가 나오면 같은 주제의 글이 이미 있는 것이니 사용자에게 묻는다.

### 2. 참고 영상 읽기 (사용자가 영상 폴더를 적었을 때만)

적지 않았으면 이 단계를 건너뛴다. 적은 영상 폴더마다 다음을 읽는다.

영상은 재료일 뿐이고, 글에서는 영상을 언급하지 않는다.

- `content.json`: 대본(sentences)과 화면(blocks). 영상이 쓴 예시 세계(테이블, 값)를 글에서도 이어서 쓴다.
- `REVIEW.md`:
  - `## 시청 후 답할 수 있는 것`: 영상의 질문과 답안. 글의 뼈대가 된다.
  - 출처 표: 다시 확인할 출발점이다(4단계).
  - `## 가장 약한 부분`: 영상에서 단순화한 곳이다. 글에서는 영상 언급 없이 정확한 내용으로 쓴다.
  - "다음 영상 후보": 글의 범위 밖이다. 글 끝의 "더 파고들 거리"에 넣는다.

### 3. 질문과 답안

`$SK/references/writing-guide.md`를 읽고 따른다.

- 주제에서 글이 답할 질문 하나를 정한다. 제목도 이 질문으로 짓는다.
- 답안을 6–10개 항목으로 쓴다. 항목마다 "주장 + 왜 + 근거(출처·계산·실험 중 무엇으로 보일지)"를 적는다.
- 참고 영상이 있으면 영상의 답안을 그대로 옮기지 않는다. 영상에서 단순화한 곳은 정확하게 쓰고, "왜"를 한 단계 더 판다.

### 4. 근거 확인

- 출처 페이지를 직접 열어, 쓸 문장이 원문에 실제로 있는지 확인한다. 참고 영상 REVIEW에 적힌 인용도 다시 연다.
- 공식 문서를 먼저 본다(MySQL이면 dev.mysql.com의 현재 버전 매뉴얼).
  - 공식 문서에 없는 내부 동작은 소스 코드나 소스 문서로 확인한다.
  - 개인 블로그는 보조 근거로만 쓰고, 참고자료에 "보조"라고 표시한다.
- 중국어 출처(CSDN, Tencent Cloud, Zhihu, Baidu 등)는 쓰지 않는다. 사용자가 읽을 수 없다.
- 수치를 직접 계산했다면 본문에는 식과 결과를, 참고자료(작업 노트)의 "계산" 절에는 자세한 과정과 가정을 적는다.

### 5. 실험 (할 수 있으면 한다)

직접 돌려서 보일 수 있는 주장은 돌린다. 탐구 글의 가장 강한 근거다.
예: 50만 행에서 인덱스가 있을 때와 없을 때의 EXPLAIN과 실행 시간, 인덱스 페이지 수, InnoDB에서 `USING HASH`를 주면 실제로 무엇이 만들어지는지.

```bash
docker run -d --name blog-mysql -e MYSQL_ALLOW_EMPTY_PASSWORD=yes mysql:8.4   # 포트는 열지 않는다
# 준비 확인. 초기화 중의 임시 서버는 TCP를 열지 않으므로, TCP로 붙으면 진짜 서버가 뜬 것이다.
# 실패하면 몇 초 뒤 다시 실행한다.
docker exec blog-mysql mysqladmin ping -uroot -h127.0.0.1 --protocol=tcp --wait=30
docker exec -i blog-mysql mysql -uroot -t < /경로/실험.sql                       # SQL은 임시 파일로 넘긴다
docker rm -f blog-mysql                                                          # 끝나면 반드시 지운다
```

- 이미지는 버전을 고정한다(`mysql:8.4`). 참고자료에 `SELECT VERSION();` 결과를 적는다.
- 환경 변수를 출력하는 명령(`docker inspect`, `docker exec … env` 등)은 쓰지 않는다.
- 본문에는 돌린 SQL과 핵심 출력 줄을 코드 블록으로 직접 보여 준다. 실험 SQL과 전체 출력은 참고자료(작업 노트)의 "실험" 절에 그대로 붙인다.
- 실행 시간처럼 매번 달라지는 값은 여러 번 재고 "이 환경에서 약 ~"라고 쓴다. 환경(맥, Docker, 버전)도 적는다.
- 임시 SQL 파일은 작업 폴더가 아니라 임시 디렉터리에 둔다. 실험이 끝나면 컨테이너를 지운다.
  이미지(`mysql:8.4`)는 남겨 두고, 보고할 때 지우는 명령(`docker rmi mysql:8.4`)을 알려 준다.
- Docker가 없거나 실험이 실패하면 건너뛴다. 출력을 지어내지 않는다.

### 6. 본문.md 쓰기

`writing-guide.md`의 구조와 문체를 따른다.

### 7. 참고자료.md 쓰기

`writing-guide.md`의 형식을 따른다. 번호는 본문과 같다.

### 8. 검토

- [ ] 본문의 사실 문장마다 온라인 출처 `[n]`이 있거나, 본문에 계산·실험이 직접 보인다.
- [ ] 본문에 `[E1]`, `[C1]`, "참고자료에 적었다"처럼 로컬 파일을 가리키는 표시가 없다.
- [ ] 쇼츠 영상 언급이 없다("영상", "쇼츠"로 검색해 확인).
- [ ] 글 끝 참고자료가 Markdown 목록(`- [n] 제목 — URL`)이다.
- [ ] 원문 인용은 실제 페이지에서 확인한 문장 그대로다(번역은 따로 적는다).
- [ ] 본문의 명령 출력은 모두 실험에서 나온 것이거나 "예시"라고 밝혔다.
- [ ] 답안의 모든 항목이 본문에 이유와 함께 나온다. 참고 영상이 있으면 영상에서 단순화한 곳을 (영상 언급 없이) 정확하게 썼다.
- [ ] 기술 용어 표기가 규칙대로다(MySQL, B-tree, buffer pool은 영어, 인덱스·해시·페이지는 한글).
- [ ] 범위 밖 내용은 "더 파고들 거리"에만 있다.
- [ ] 실험 컨테이너를 지웠다(`docker ps -a`에 `blog-mysql`이 없다).

### 9. 보고

사용자에게 짧게 알린다.

- 두 파일 경로와 여는 명령: `open "z_블로그작성/<N>_<slug>/본문.md"`
- 제목, 질문, 목차(장 제목만), 분량(글자 수, 읽는 시간 어림)
- 새로 보인 근거(실험이 있으면 핵심 결과 한 줄). 참고 영상이 있으면 영상에서 단순화했던 곳과, 글에서 확인한 정확한 내용을 보고에 적는다(글에는 쓰지 않는다).
- 확인하지 못해 뺀 주장이 있으면 그 목록
- 남은 Docker 이미지와 지우는 명령

## 하지 말 것

- 근거 없는 사실 문장, 지어낸 명령 출력·실행 시간
- 본문에서 쇼츠 영상 언급, 로컬 파일(`참고자료.md`)을 근거로 가리키기
- 중국어 출처
- 환경 변수를 출력하는 명령
- 영상 폴더(`<N>_<주제>/`) 안의 파일 고치기. 영상 폴더는 읽기만 한다.
- git 사용(사용자가 git을 쓰지 않기로 했다)
- `z_블로그작성/` 밖에 결과 파일 만들기
